# B09 preflight

## Current seams

- `sync::engine::run_scan` (`src-tauri/src/sync/engine.rs`) returns early before creating a scan for auth reset/already-running races; they lack a scan ID and must not notify. `scan_inner` exits without a scan when no client exists. Otherwise `db::start_scan` yields the durable ID. Auth expiry finalizes `auth_expired`, persists diagnostics, invokes `notify_auth_expired` once per auth episode, then returns. Auth-reset cancellation finalizes `cancelled` and returns. Normal completion finalizes `ok`, `partial` (failed courses or errors), or `cancelled`, persists diagnostics, then calls `notify::dispatch(app)` for change events. This finalization block is the scan-failure notification seam; add notification after terminal persistence, including handled early-finalization paths only when qualifying.
- `notify::dispatch` in `src-tauri/src/notify.rs` batches unnotified change events. Its native path requires `notifications_enabled` and no quiet hours; Telegram has its own global setting and quiet-hour check. `notify_auth_expired` uses `notify_auth`; currently its native path checks global enable but not quiet hours, while Telegram does. Do not change that existing auth policy in B09. Failure alerts should be native only and require both `notifications_enabled` and `notify_scan_failures`, outside `Settings::in_quiet_hours`.
- `Settings` (`src-tauri/src/settings.rs`) uses `#[serde(rename_all="camelCase")]`; notification fields have no serde defaults. `Default` enables each category. Additive precedent: field-level `#[serde(default = "...")]` plus helper (`update_auto_check`, `mirror_enabled`). Without it, omitted JSON fails deserialization and `db::load_settings` discards the row for defaults. Set `notify_scan_failures: bool`, helper/default `true` to match existing notification categories, and test missing-field deserialization. TS `Settings` is required-field typed; add `notifyScanFailures: boolean`. `settingsDraft` compares whole objects, so add it to every typed Settings fixture: `tests/settingsDraft.test.ts`, `tests/helpers/data.ts`, `tests/settingsAbout.test.tsx`, `tests/settingsLayout.test.tsx`, `tests/axeViews.test.tsx`, and compiler-discovered literals. No API/command change: existing `setSettings(Settings)` transports it; 04C0 owns common API/commands.

## Behavior contract / unresolved lease

Notify once for a finalized scan when `courses_failed > 0` or status is terminal `partial`/`failed`; success never notifies. Cancellation (including auth-reset cancellation) is not failure. `auth_expired` remains exclusively on the existing once-per-auth-episode reminder path, avoiding duplicate alerts. Baseline success is silent; baseline partial/failed still qualifies under the frozen contract. Use generic copy: “Quanta scan incomplete” / “Some courses could not be checked. Open Quanta Pulse to review scan details.” Never include raw error summaries, URLs, course/resource names, IDs, or credentials.

Deduplication identity is `scan_runs.id`, not error text or scan outcome. DB has no scan marker; event `notified_at` cannot represent scan alerts, and a process-local set is not restart-safe. Durable at-most-once needs a scan-row marker (or durable scan-ID key) atomically claimed before delivery; even delivery failures remain claimed. This needs a narrowly scoped `src-tauri/src/db.rs`/additive migration lease, serialized under contract 00's DB rule. Without it, do not claim restart-safe deduplication. Test distinct IDs each alert and duplicate ID only once.
