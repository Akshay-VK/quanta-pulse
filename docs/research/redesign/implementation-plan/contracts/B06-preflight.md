# B06 preflight

`rebuild_baseline(Some(course_id))` JSON-serializes IDs under `settings.rebaseline_courses`; `None` deletes `baseline_established`. `scan_inner` snapshots both at scan start. The global `baseline` flag suppresses all resource diffs; otherwise matching course markers suppress that course's diffs. The first-run global marker is written only when discovery is neither cancelled nor carrying errors, so incomplete first scans remain silent on retry.

The per-course marker lifecycle is too broad: after any non-cancelled discovery, engine deletes the entire marker key. A different course can fail or have partial page traversal (`courses_failed`/`errors`) while another succeeds; even a partial error in the reset course can therefore consume its marker. Cancellation and early auth-expiry/transaction failures currently return before this deletion, preserving markers. Global reset is separate: it keeps global baseline mode until a fully clean discovery. It suppresses changes app-wide; per-course reset suppresses only selected courses. Neither path should delete history or saved files; reset changes diff classification only.

## Minimal design

Keep the existing JSON settings key and API signature. Discovery must expose the external IDs whose course traversal reached terminal `Success` (pages and required details, where applicable); engine maps those IDs through its existing course IDs and removes only successfully completed IDs from the persisted reset set. Preserve IDs absent from the scan, failed, partial, or interrupted. Do not infer success from `courses_scanned` or global `errors`. Important unknown: whether detail-fetch failures currently affect terminal course status—verify the existing observer/status aggregation before defining “complete.” The current `Discovery` carries only aggregate counters/errors; the precise smallest handoff may be adding successful external IDs there or deriving them from its existing per-course observation collector. No migration is needed; settings already persists across reopen. Keep initial global baseline behavior unchanged. Global reset remains pending until a whole uncancelled, error-free scan; per-course success may consume that course's marker despite another course failing.

## Lease and proof

Prefer one coherent backend packet: engine lifecycle plus the minimal discovery success signal and deterministic Rust tests. Lease `src-tauri/src/commands.rs` only if reset write semantics need change; no API/type ownership is implicated. Candidate exact lease: `src-tauri/src/sync/engine.rs`, `src-tauri/src/quanta/discover.rs`, and focused test file(s); serialize any shared-file ownership before implementation.

Use temporary SQLite DBs and a local HTTP fixture server only. Cover: clean initial baseline emits zero new events; partial course failure then retry stays silent for reset course and consumes its marker only after that course succeeds; cancellation retains marker; close/reopen DB between failed attempt and retry; unrelated successful course does not consume a failed course marker; new course discovered during global reset remains silent; global reset persists across partial scan then clears after clean completion; existing event/history and mirror-file rows survive reset. Assert persisted marker set and emitted event kinds after each scan. Exact fixture routes/content and detail-completion semantics are unknown and should follow the existing discovery test harness, not be invented.
