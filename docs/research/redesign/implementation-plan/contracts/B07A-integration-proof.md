# B07A coordinator integration — 2026-11-16

The coordinator strengthened the ordinary DB-failure regression to require both the saved bytes and index to survive. It failed against the original unlink-first implementation. The recovery pass stages bytes with a same-directory rename, restores them on statement/commit failure, and retains a retryable stage location when compensation or final cleanup fails. The independent recovery review found scope pruning could discard that metadata during ordinary process use. New expiry/capacity regressions reproduced the defect; recovery-bearing scopes now bypass expiry/eviction, and an all-recovery capacity limit fails closed. Normal scopes still expire after ten minutes, and completed scopes are removed.

Coordinator result semantics supersede earlier handoffs: `removed` counts captured entries whose file/index cleanup completed in this invocation, including idempotent missing entries. An entry with outstanding staged cleanup is only in `failed`, never also in `removed`. Retrying the same scope completes only remaining failures. `MIRROR_DELETE_SCOPE_EXPIRED` requires renewed confirmation; `MIRROR_DELETE_RECOVERY_PENDING` requires finishing outstanding cleanup before another scope can be retained.
