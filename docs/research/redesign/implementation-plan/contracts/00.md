## Task 01: appearance

Current exported model and owner:

```ts
export interface AppearancePreference {
  version: 1;
  mode: ThemeMode;
  palette: typeof PALETTES[number]["value"];
  accent: typeof ACCENTS[number]["value"];
  density: "comfortable" | "compact";
  monospace: boolean;
}
export const DEFAULT_APPEARANCE: AppearancePreference;
export function readAppearance(storage: StorageReader): {
  preference: AppearancePreference; future: boolean;
};
export function saveAppearance(storage: AppearanceStorage,
  preference: AppearancePreference): PersistenceResult;
export function resolveAppearance(preference: AppearancePreference,
  systemDark: boolean): { mode: "light" | "dark"; tokens: Record<string, string> };
export function applyAppearance(root: HTMLElement,
  preference: AppearancePreference, systemDark: boolean): "light" | "dark";
```

`useTheme()` is the sole React owner: `{ preference, changeAppearance(patch), resetAppearance(), persistence, themeMode, setThemeMode(mode), resolved, toggle() }`. It owns synchronous first-frame/live application, local persistence and OS appearance subscription. **Approval update (2026-11-15):** `AppearancePreference` includes `monospace:boolean`; version-1 records missing/invalid values resolve to `false`, reset turns it off, and enabling it applies Geist Mono to every UI typography role. Task 13 consumes `preference.monospace` and `changeAppearance({ monospace: boolean })`; it owns the control UI. Appearance remains outside Rust `Settings` and the draft controller. Preserve unknown future records without overwriting them. ## Shared frontend ownership

- `App.tsx` remains sole route, selection, material-execution, Settings-navigation-guard and final read-on-inspect integration owner. A view emits intent through its `DetailsAdapter`; selection/focus/preview alone does not mark read.
- `DetailsAdapter` is `selected: DetailSelection|null`, `selectResource(resource, origin, restoreFocus?)`, `selectChange(change, origin, resource?, restoreFocus?)`, `selectScan(scan, origin, restoreFocus?)`, `clear()`. Identity is `resource:<id>`, `change:<id>`, or `scan:<id>`; owner is a `ViewId`. Do not create a second details selection owner.
- `InboxItem.eventIds` is the exact grouped event snapshot; new arrivals are excluded. For a resource selected in other views, use B05's complete snapshot seam above, not loaded page rows. Optimistic state changes require captured IDs and rollback on failure.
- `CalendarView` owns only Agenda/Activity tabs; `ActivityCalendar` owns selected day. Inspection replaces the selected-day panel while its day selection remains restorable.
- `SettingsView` retains the exported `SettingsNavigationController { dirty, valid, saving, error, save(), discard() }`; `App` alone guards navigation. Appearance remains a separate immediate owner.
