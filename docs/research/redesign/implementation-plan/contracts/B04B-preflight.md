# B04B preflight: scan observation boundaries

## Observed flow (facts)

- `run_scan(AppHandle, reason)` owns the running/cancel gate, invokes `scan_inner`, then clears the gate and publishes completion (`src-tauri/src/sync/engine.rs:25-72`). `scan_inner` loads limits/baseline/client, creates aggregate scan history, and calls discovery (`engine.rs:75-126`).
- Discovery emits scan-wide phases only: `Listing courses`, `Scanning courses`, `Reading materials`; each `Progress` carries phase/done/total, without course identity or timestamps (`src-tauri/src/quanta/discover.rs:49-57,129-155,166-177,275-304,336-344,434-442`).
- Per-course page crawls run in a bounded `JoinSet`; results identify external course IDs, resources, and page errors, but no task start/end instants. Joined errors increment aggregate failed counts (`discover.rs:166-205,271-304`). Course cancellation stops scheduling/marks overall cancelled after joins (`discover.rs:171-178,307-309`).
- Material detail requests are a separate concurrent pass, returning resource-level failures; they do not retain course-level completion state (`discover.rs:317-363,434-463`). Scan transaction upserts courses/resources and marks course scan status; cancellation/reset and auth-expiry have early terminal branches (`engine.rs:135-175,191-220,353-369,407-442`). Baseline suppresses change classification effects and only establishes its marker after a complete error-free scan (`engine.rs:262-280,394-399`).
- Frozen DTO contract requires per-course actual start/completion, terminal `success|partial|failed|cancelled`, observed steps with timestamps/status/error; legacy detail may be null and historical steps must not be inferred (`contracts/00.md:41`).

## Recommendation (not current behavior)

**Additional lease:** B04B currently leases only `src-tauri/src/sync/engine.rs` and focused engine tests (`tasks/B04B.md:8-16`). Grant one narrow serialized lease to `src-tauri/src/quanta/discover.rs` (and its focused tests); do not touch DB/API/DTO files, scheduler, or UI. Storage helper/function names remain the B04A consumer pointer until its contract lands.

Extend discovery with an internal typed observer callback, passed alongside `ProgressFn`, emitting actual boundaries with course external ID and timestamp: course-work-start (after semaphore acquisition, before first course fetch); course-pages-terminal (success/partial/failure/cancelled, actual error); detail-work-start and detail-work-terminal per course, with resource outcome/error. Callers are `discover_all`'s course task and join-result handling, plus detail task creation and join-result handling (`discover.rs:171-205,275-304,344-363,434-463`). A small per-course accumulator can close the course at the actual last detail completion; courses with no detail targets close at page terminal. Do not use progress counts to invent identity, timestamps, or step completions. `Listing courses` is scan-global and must not be assigned to each course. Persist only observed step boundaries.

For deterministic engine proof, extract a production-used internal scan core from `scan_inner` at the discovery/persistence seam: inputs are the existing client, limits, cancel token, baseline inputs and a small diagnostic sink/storage adapter; keep `run_scan`/Tauri event, mirror, notification and scheduling orchestration intact. The adapter should accept the real observer records and B04A persistence contract. Test this same core with a temporary SQLite connection, deterministic clock/observer, and a local HTTP fixture serving dashboard/course/material pages. Avoid `AppHandle` construction and test-only production configuration. Reopen DB and assert persisted course/step times/statuses and errors, including partial, failed, cancellation and silent baseline; legacy detail remains absent. Keep the inventory transaction/mutex boundaries intact: never retain `state.conn()` across a helper that reacquires it, and diagnostic write failures follow B04A semantics without rolling back aggregate history.

**Risks:** cancellation may leave courses never started; leave them without fabricated rows. A reset/auth-expiry early return must terminalize only courses actually observed. Cancelled/failed partial discovery must not advance B06 rebaseline markers; preserve current reset-marker behavior. Observer timestamps should be captured at callbacks, not reconstructed from joins or totals.
