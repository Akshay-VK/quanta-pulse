## Scope

Expose Rust `Settings.notify_scan_failures` as required camelCase `notifyScanFailures` in TypeScript settings and add it to settings draft/UI controls and fixtures according to the existing Settings organization. Use the existing `setSettings(Settings)` command/API; add no command or invoke wrapper.

## Acceptance

- The setting is represented as `notifyScanFailures: boolean` in the frontend `Settings` type and every applicable settings fixture.
- The Settings UI clearly controls native alerts for incomplete scans, persists through the existing draft/save path, and preserves edits under navigation guarding.
- Tests cover default/current draft comparison and toggling/save behavior.
- Run frontend lint, tests, and build; coordinate shared command/type/API integration with the root integrator.

## Blocker

Do not start until B09A's native contract is integrated and available. The consumer relies on `notifyScanFailures` defaulting true in Rust for pre-existing saved settings. This packet does not authorize command/API/registration edits; the existing `setSettings` transport is sufficient.
