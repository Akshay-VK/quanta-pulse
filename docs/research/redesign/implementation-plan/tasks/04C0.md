# 04C0 — Complete resource event snapshot API

Approved backend/API prerequisite under 04C. Start after B05A and the B07B shared API-wrapper lease. This task does not implement any list surface or accept 04C/task 04.

## Frozen contract

Expose `api.snapshotResourceEventIds(resourceIds: number[]): Promise<number[]>`, invoking `snapshot_resource_event_ids` with `{ resourceIds }`. Return the complete stable ascending, unique event IDs associated with exactly those resources, both read and unread. Exclude baseline and calendar-suppressed events. Ignore Inbox dismissal and History clear-watermark state. The returned array is a membership snapshot: later events cannot enter existing captured-ID read-state or dismissal mutations.

Reject any nonpositive resource ID. Duplicate resource IDs are harmless. An empty array returns an empty array without widening scope. There are no list/page/default caps. Handle more selected resource IDs than SQLite's bind-variable limit by chunking the query and returning a sorted unique union. Snapshot reads must not change event/read state. Keep the singular unread-only API for I01 unchanged.

- Add an exact invoke API test for command name and camelCase argument.
