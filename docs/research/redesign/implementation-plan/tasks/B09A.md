# B09A — Native scan-failure notification core

Parent: B09 umbrella #43. Blocked by task 00 issue #15. Native-only implementation slice; TS/UI wiring is B09B.

## Scope

Add backward-compatible Rust `Settings.notify_scan_failures` defaulting to true, durable per-scan at-most-once claim state, and a generic native alert after qualifying scan finalization. Keep auth reminders and Telegram policy unchanged. No scan record is created for no-client/rejected scans.

## Acceptance

- Legacy settings JSON missing `notifyScanFailures` deserializes with true and retains unrelated values.
- Alert eligibility requires global native notifications and scan-failure preference enabled, and current local time outside configured quiet hours.
- Only persisted finalized scan rows qualify: `partial`/`failed`, or another non-excluded terminal outcome with failed courses. Cancellation, `auth_expired`, successful scan, absent ID, unfinished row, and deleted row do not qualify. Partial/failed baseline scans qualify; successful baseline stays silent.
- One atomic claim per `scan_runs.id`, before native sink attempt; the marker survives restart and is removed with History deletion. Sink failure remains claimed.
- Fixed generic title/body contain no scan/course/resource identifiers, raw errors, URLs, or credentials. Native notification only.
- Focused and full Rust library tests plus Windows `cargo check` pass.
