# Quanta Pulse search and academic expansion plan

The sidebar now opens course folders directly from the course list. The next search release should make those folders discoverable from the command palette and carry the same results into Library. Independently, prepare the scan pipeline for separate academic collectors and validate Quanta’s student-facing sources. Ship assignment details first, then grades, then attendance where the deployed report supports it.

## Search

The [command palette](../../src/components/CommandPalette.tsx) searches courses, files and app commands. Its [parser](../../src/lib/paletteQuery.ts) supports `course:`, `type:`, `is:` and `due:`, and splits terms on whitespace, so a quoted multiword course name cannot round-trip. [Course Materials](../../src/lib/courseLibrary.ts) matches a literal substring across title, type and path. [Telegram’s resource search](../../src-tauri/src/core/search.rs) uses the [SQLite title/course substring query](../../src-tauri/src/db.rs), newest first. Each surface currently has its own search scope and ranking. File body search has no persistent index.

| Step | Deliverable | Acceptance |
| --- | --- | --- |
| S1. Desktop metadata | Add explicit Everywhere, Course and Folder scopes, with the current folder as the default in its Materials search. Make course names and aliases, nested paths, file titles and types searchable. Add folder hits that reveal the branch and open it. Keep deep links by stable IDs and paths. | `course:"ECOM F222" lecture 4` works with quoted aliases and combined terms. A hit for `Week 05 / Lectures` opens the correct course even when another course has the same path. Unmatched queries remain visibly empty. |
| S2. Results and filters | Use shared desktop query and ranking logic across the palette and Library. Prefer exact titles, then title prefixes and term matches, then path/course metadata, with recent source date and ID as tie-breakers. Preserve chips and text in See all results. Expose type, date, unread and saved filters already supported by local data. Use the configured timezone for deadline filters. | Identical scope and filters produce the same file order. Keyboard users can open a folder, inspect a file or expand to full results. Cases cover punctuation, diacritics, duplicate titles, renamed courses, empty queries and midnight boundaries. |
| S3. Local file contents | Measure metadata performance first. Prototype a rebuildable SQLite FTS5 index for supported text and text-layer PDFs already saved locally, reusing safe extraction in [core/text](../../src-tauri/src/core/text.rs) where supported. Index offline with size/time bounds and show an explicit content match with a snippet. Keep Telegram on its current metadata scope pending a separate decision. | Benchmark 5k, 25k and 100k metadata rows and capture input-to-result latency and lock time. Verify no downloads on query, content replacement/removal and rebuild, and clean fallback when extraction or indexing fails. Publish supported formats. Keep OCR and private academic values outside this index. |

## Backend refactor and delivery

The [architecture audit](2026-11-15-codebase-architecture-audit.md) captures the source-era findings and [proposed scan boundaries](2026-11-15-architecture/refactor.mmd). The [scraping report](2026-11-15-academic-scraping-expansion.md) and [pinned Moodle source inventory](2026-11-15-moodle-academic-data-sources.md) establish candidate sources. They leave Quanta’s installed version, course settings, permissions and side effects open. The [academic flow diagram](2026-11-15-architecture/academic-expansion.mmd) shows where collectors, domain reconciliation and local readers fit.

1. **Verify and fix existing failure paths.** Reproduce the remaining audit cases on the current branch. Prioritize scans that consume a baseline after persistence fails, truncated discovery that can advance misses, publication of the verified SSO client and backup triggering across migrations. Add regressions before extraction. Retain the current bounded course-color assignment and existing History event pagination.
2. **Extract collection and durable reconciliation.** Keep the scheduler and Tauri command surface. Move announcement-specific and material-specific request, parse and merge policy behind their collectors. Keep course traversal, cancellation, body limits and request budgeting shared. Reconcile in SQLite with an explicit committed outcome, then publish events and queue effects. Preserve existing resource IDs, paused courses, quiet baselines and the two-complete-scan missing threshold for materials. Prove parity with current HTTP fixtures, then inject partial discovery, cancellation and commit failure.
3. **Isolate academic state.** Scope records and baselines to a verified student identity. Fence fetches and publication by session generation across logout, reset or account switch. Add additive, versioned migrations and a tested backup/restore path. Track coverage by course and domain: complete, partial, denied, unsupported, offline or stale as applicable. A confirmed expired login can stop sync. A denied optional report leaves materials and other successful results usable. Keep private values out of generic diagnostics, desktop notifications, Telegram and metadata search by default. Test late responses from a prior student, partial coverage and restart behavior.
4. **Validate the read sources in parallel with the refactor.** With an authorized student session, record route and capability evidence and capture sanitized structural fixtures. Verify Moodle version, locale, date/timezone, report visibility and the ID joins for course modules, activity instances, grade items and attendance sessions. Prove polling policy before enabling it. Assignment detail can mark activity-view completion, and attendance rules can depend on course logs or other activity completion even when an HTTP read submits no form. Use only verified student read routes. Keep self-marking, mobile attendance callbacks, submission flows and staff reports outside collector capabilities. Use session AJAX only when the installed service explicitly supports the function and learner permissions. Disable unattended collection for a domain with unresolved effects.
5. **Deliver assignment details and Agenda enrichment.** Start with existing assignment discovery and corroborate the effective deadline and visible submission state from a verified student source. Define distinct unknown, unsubmitted, draft, submitted and reopened states and preserve user/team overrides and submission attempts. Project the personalized deadline into Agenda without duplicate entries. Suppress routine due reminders for known submitted work, and keep existing reminders when status is unknown. Test individual extensions, teams with outstanding confirmations, reopening, missing dates and existing-store rollout. Open Quanta for submissions.
6. **Deliver student-visible grades.** Use the current learner’s course user report where available. Display numeric, scale and text grades, categories, feedback and Moodle’s displayed totals. Distinguish unreleased, hidden, blank, zero and denied. Hold the last successful permissible snapshot on transient errors, label stale coverage and only record changes after a quiet successful baseline. A grade that becomes restricted must cease to appear as current. Cover hidden components of totals and stable identities for manual grade items. Keep raw feedback out of logs and sanitize it before rendering.
7. **Deliver attendance only where verified.** Detect the installed report per course and use the current student’s read view after the source check. Preserve instance/session identity, course/group coverage, date filters, status labels, points and the report’s denominator. Distinguish future and unrecorded sessions from explicit absences. Show the report’s own summary and freshness alongside a Quanta link. Cover multiple activities, partial pages, custom statuses and unsupported courses. Treat custom portals and institutional eligibility rules as separate discovery work.

## Release gates

- **Refactor** — Existing material and announcement fixtures produce the same IDs, paths, diffs and local state. Failed writes never publish success, and incomplete scopes never advance absence. Cargo tests exercise loopback HTTP and temporary SQLite. Existing frontend checks pass on wire changes.
- **Each academic domain** — A known student-facing source, sanitized fixtures, budget and polling policy, independent UI/read failures, a quiet first successful baseline, ownership and privacy tests, and an authorized smoke test comparing Pulse to Quanta. Rollback disables the collector and retains compatible local data. Restore the tested backup when schema compatibility requires it.
- **Search** — S1 can ship independently. S2 checks query authority, pagination consistency and stable folder destinations. S3 requires supported-platform extraction tests and representative performance measurements before enrolling local content.
