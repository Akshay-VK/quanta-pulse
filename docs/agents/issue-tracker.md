# Issue tracker

Use GitHub Issues in [Akshay-VK/quanta-pulse](https://github.com/Akshay-VK/quanta-pulse) for specs and implementation tickets. Pass `--repo Akshay-VK/quanta-pulse` to every `gh` command; the CLI's implicit repository resolves to the upstream fork.

Specs are parent issues and approved tickets are native sub-issues. Represent dependencies with native blocking relationships and keep the ticket body readable with parent and blocker links. Apply `ready-for-agent` only to approved, fully specified work. Preserve existing labels.

Before publishing, confirm the explicit repository and that Issues is enabled. Search matching titles before creating issues. Read back each issue, label, parent, and blocker edge after publication. Never close a parent or ticket before its approved acceptance workflow. The tracker is not a PR request surface; resolve work through the accepted integration workflow or documented final acceptance.
