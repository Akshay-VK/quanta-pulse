## Collection ownership and attention

[App collection ownership](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/App.tsx#L103) instantiates the [attention query module](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/hooks/useAttention.ts#L6). Active Inbox listing uses complete backend totals with 50-item pages; unfiltered `queryInbox({})` independently supplies unread item/course counts. App no longer requests legacy Dashboard resources/events or raw unread counters. Filter changes and background `sync:done` refreshes invalidate old requests; background refresh starts at page zero. Failed queries retain the previous snapshot with error feedback. Resource enrichment traverses every 2,000-item resource page so inspection does not misclassify a surviving resource beyond the old default cap as an orphan.

[Inbox](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/views/InboxView.tsx#L27) separates All/Unread attention from course, change type (including announcements), and search. One backend group is one row; orphan events use shared recorded-change details. Explicit read/unread mutates the displayed group's event IDs. Bulk read/dismiss captures `snapshotInboxEventIds` at activation, before confirmation, across unloaded pages. Confirmation retains those IDs even when new changes arrive. Ref guards and disabled controls prevent duplicate activation. Mutation failures retain rows, attention state, and a retryable confirmation; no optimistic acknowledgment or success message masks failure. Inspecting material never acknowledges it.

Dismissal uses `dismissInboxEvents`; History is retained. [Permanent History deletion](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/App.tsx#L403) is independently named and confirmed, calls `deleteHistory(true)`, and explicitly deletes all changes (including dismissed ones) and scan diagnostics while retaining resources/saved files. The existing loaded History read action is labeled “Mark loaded history read” and uses explicit IDs; it makes no claim to cover unloaded history. History tabs are Activity and Scan history. The compatible internal route identifier remains `today`; `today`, `dashboard`, and `inbox` all open the visible Inbox.

## Due dates and shared inspection

[Pure date selectors](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/lib/agenda.ts#L4) accept a controlled clock and resolved timezone. Valid configured IANA timezone wins, followed by OS timezone, then UTC. Date-only values retain their source calendar date and acquire no submission time. Timestamp values retain their raw source and display exact local dates, time, and timezone context. The selectors omit invalid values, deduplicate canonical resource identities, distinguish repeated DST instants, and use Monday-first weeks. “Past due dates” describes dates rather than inventing completion/submission status.

[Agenda](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/views/AgendaView.tsx#L19) is Calendar's default; [Activity calendar](https://github.com/Akshay-VK/quanta-pulse/blob/bfdd4a66ad7efea02fa784766112f6c81eff8857/src/views/ActivityCalendar.tsx#L113) retains month/day navigation, keyboard controls, recorded-event details, scan diagnostics, and detection-date labeling. Agenda reads every matching due-inventory page before publishing a snapshot, independently of baseline/events/Inbox dismissal. It defaults to monitored courses, permits an explicit paused-course filter, groups Past due dates/Today/Tomorrow/This week/Later, and expands past dates only on request with 20-row pagination. A separate unfiltered due snapshot supplies Inbox's next five entries within seven local calendar days (today through six days ahead), excluding past instants. Due soon never contributes attention badges.

Agenda refresh errors retain dated resources; initial failure is separate from a successful empty inventory. Shared resource selection remains keyed by canonical identity, updates known due-date metadata on refresh, and clears when removed. Shared details show the raw due source plus local date context; source-unavailable warnings remain independent of saved-copy actions. `DetailsAdapter` and `MirrorProvider` interfaces remain unchanged. Rows switch to their measured two-line layout below 800px to preserve readable titles with the new date/attention controls; theme tokens and density remain owned by the appearance implementation.
