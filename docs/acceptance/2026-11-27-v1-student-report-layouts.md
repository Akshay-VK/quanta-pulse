# Quanta student report layout evidence

On 2026-11-27, a signed-in student inspected a grade report, a monthly Attendance activity report, and course navigation in Quanta. This records the structure of those views for [V1 #64](https://github.com/Akshay-VK/quanta-pulse/issues/64). The observations below describe rendered pages from one account. Pulse's request behavior and cross-account permissions were outside this check.

| Surface | Observed in Quanta | Implication for Pulse |
| --- | --- | --- |
| Grades | The `table.user-grade` report has Grade item, Grade, and Range columns. Semantic header references connect each value to its item and column. Parent category classes, nested category headers, and spacer rows describe the hierarchy. Moodle renders category and course totals separately from manual items. An item can show a dash in its Grade cell while still showing a range. | The existing reader recognizes these columns, relationships, and total types. Preserve the order and published totals, and keep a dash distinct from numeric zero. The reader also requires an enclosing element bound to the verified owner. The supplied table fragment begins inside that boundary. |
| Attendance report | The active report is **This course**, filtered by **Months**. The page renders Date, Description, Status, Points, and Remarks. A row can display `?` for status and a points fraction with an unknown numerator. A separate summary names taken sessions, points over taken sessions, and percentage over taken sessions. The rows in this view have no stable session IDs. | The deployed layout needs an adapter for its semantic columns and labeled summaries. Store the source's displayed date and time, preserve unknown status and points, and treat the month as a scoped snapshot. Use Moodle's summary labels and values directly. |
| Attendance scope | Month navigation shifts the date window. The report also exposes other windows and separate All courses and All sessions modes. No page-number pagination was visible in this monthly sample. | Keep date windows separate from pagination and avoid inferring complete course history from the monthly view. The other modes and their coverage need separate evidence. |
| Course navigation | Attendance appears as a Moodle activity under nested course sections. A course can link to multiple distinct attendance activities, including lecture and tutorial sections. The activity links expose Moodle course-module IDs. | Keep activities separate by module ID and bind each candidate to the selected course. The module ID alone does not establish the plugin instance ID, verified owner, or the student's section membership. |

## Remaining verification

- The student confirmed `/grade/report/overview/index.php` as the Grades overview path and `/course/user.php?mode=grade&id=<course-id>&user=<student-id>` as a route to detailed grades. The latter is Moodle's course profile report, which delegates rendering to the configured grade report plugin and emits a course user report view event. [Moodle Grades overview](https://docs.moodle.org/405/en/Overview_report#Grades) · [Moodle course profile report controller](https://raw.githubusercontent.com/moodle/moodle/MOODLE_405_STABLE/course/user.php)
- The student confirmed that Pulse's direct route, `/grade/report/user/index.php?id=<course-id>`, displayed the same grade items and totals for the populated course. Upstream Moodle uses the signed-in student when `userid` is omitted. In Quanta's rendered Elements panel, the direct-child selector matched zero elements and `.user-report-container[id^="user-report-"] table.user-grade` matched exactly one. Pulse now allows intermediate markup and checks the nearest report container against the signed-in student. The loopback regression uses synthetic markup with this structure and rejects a wrong-owner container nested under the correct owner. The browser check confirms the rendered ancestry and ID format. A live Pulse run still needs to verify the exact owner binding on the fetched response. [Moodle gradebook user report controller](https://raw.githubusercontent.com/moodle/moodle/MOODLE_405_STABLE/grade/report/user/index.php) · [Moodle grade report renderer](https://raw.githubusercontent.com/moodle/moodle/MOODLE_405_STABLE/grade/report/user/classes/report/user.php)
- Attendance needs a reliable owner and course binding for the returned report, evidence for the report's date and group scope, and a model for snapshots whose plugin instance or session IDs are unavailable. The existing collector expects an explicitly identified fixture envelope and does not accept the observed report.
- A live Pulse-versus-Quanta comparison and evidence on the effects of repeated report reads are still pending. To compare Grades, sign in with Google in Pulse, open the populated course under **Library → Grades**, and choose **Check grades**. This reads one course under the verified session and writes to the existing owner-scoped local store. Opening Grades or using **Reload** reads that local store. Report agreement can be recorded without sharing marks. The scheduler does not invoke this action.
- Visible automatic-recording remarks describe how some attendance records were attributed. They do not establish what caused the recording or what a Pulse request would do. The attendance research describes Moodle's report-view logging and potential interactions with automatic marking.
